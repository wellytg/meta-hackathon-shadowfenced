What it is

Your words. Your boundary.

Keep sensitive details on your side of the conversation. Shadowfenced sits between you and the AI. It reads what you type on your own computer, spots the sensitive parts, and only lets clean or redacted text leave. The real values never leave your side.

You → AI = risk when your raw text travels: once it leaves your machine it can be stored, logged, or quoted back. The fence below keeps raw values on your side and lets only placeholder tags cross.

The problem, in three steps

What happens to what you type

  1. (a) How most AI tools work

    You type a request carrying an email address, a contract clause, and an API key from a .env file — and the whole thing travels to the agent. The app sees your raw text.

    Illustration — sample data, nothing is sent.

  2. (b) Where it goes wrong

    Once the raw text arrives, it can be stored, logged, or quoted back. You cannot pull it back. That copy lives outside your machine.

    Illustration — sample data, nothing is sent.

  3. (c) With Shadowfenced

    A membrane on your machine checks every message first. Secrets are blocked; the email, contract clause and API key are swapped for placeholders like [PII_EMAIL_1], and the real values are restored locally when the answer comes back.

    Illustration — sample data, nothing is sent.

Three things to know

  1. 01

    Underlines as you type

    Sensitive text is underlined in the composer before you hit send, so there are no surprises.

  2. 02

    Only clean or redacted text leaves

    Anything risky is blocked or swapped for a placeholder like [PII_EMAIL_1]. The cloud only ever sees the tag.

  3. 03

    Real values come back on your machine

    The AI answers with the same tags, and your computer swaps the real values back in. Nothing to copy, nothing leaks.

How it works

Four tiers, all on your side first

  1. 1 · Tier 1 code scan

    Every keystroke is checked by deterministic code — no model call. Proven findings (emails, secrets, codenames) are underlined in the composer; ambiguous spans are marked for review.

  2. 2 · The gate decides

    At send time the gate issues one decision: ALLOW clean text, REDACT it with placeholder tags, BLOCK planted canary tokens, or HOLD anything ambiguous or carrying a sensitivity cue.

  3. 3 · Tier 2 local review for holds

    Held messages are reviewed asynchronously by Muse Glimmer on this machine — never by sending your raw text away. You get an anchored choice: send without the flagged part, or don't send. Nothing is released without your say.

  4. 4 · Receipt and restore

    Only clean or redacted text reaches the upstream model — Llama 3.2 on this machine by default, or Meta Muse Spark in the cloud when you configure a key. Answers come back with tags and are restored locally; every turn is written to a hash-chained decision log you can verify.

Trust

What stays on your machine

  • Real values. Only placeholder tags cross the boundary; the mapping never leaves your side.
  • Your choices. Redact / keep decisions apply immediately and only here; custom rules stay in a local file.
  • Your drafts. Chat sessions live in the page memory only — never stored, never uploaded.

Limits, stated plainly

  • Model-suspicion underlines are hints; they are always re-checked by code at send time.
  • Anything the checker cannot clear is held, and unknown states fail closed — never treated as safe.
  • Attachments are scanned before sending; unscannable files are held rather than sent blindly.
  • The cloud provider you pick still receives whatever clean or redacted text you approve.

Install

Running on your machine in 3 steps

  1. 1 · Clone

    git clone https://github.com/wellytg/meta-hackathon-shadowfenced.git

  2. 2 · Install

    pip install -e ".[dev]" needs Python 3.11+.

  3. 3 · Run

    python -m uvicorn shadowfenced.app:app --app-dir src --host 127.0.0.1 --port 8765 then open http://127.0.0.1:8765.
