# T58 — Route-table tests must work on FastAPI 0.162 (CI) as well as 0.115 (local)

GitHub CI installs FastAPI 0.162; this PC has 0.115. On CI, `tests/test_t38_chat_ui.py::test_log_events_route_registered`
fails with `KeyError: '/api/ext/pairing/regenerate'`: it builds a table from `app.routes`, and on newer FastAPI the
routes of included routers (`ext_api.router`) are not listed there with their full path in the same way. An earlier
fix (T21b, see `tests/test_t21_rules.py` around `app.openapi()["paths"]`) solved the same problem by reading the
OpenAPI schema instead.

Fix every test in `tests/` that reads `app.routes` to look up paths (search for `app.routes` and `.routes`): use
`app.openapi()["paths"]` (path → lowercase methods), or a small shared helper in `tests/conftest.py` that works on both
versions. If a route is deliberately hidden from the schema (`include_in_schema=False`), check it with a TestClient-free
call to the endpoint function or `app.url_path_for` instead. Do not change application routes for the test's sake.
Run `python -m pytest -q -p no:cacheprovider` and `python scripts/ci.py`. Do not commit.
