# T46 — Visuals in Classic style made with Muse Image

The repo needs one consistent set of graphics in the Classic style (paper background, ink black, hard 2px outlines,
square corners, safety orange for blocked, amber for review, steel blue for allowed, Windows 3.11 pixel feel).
Reference: `docs/assets/storyboard_v1.png`, an 8-panel storyboard the owner likes. It has narration text under the
panels, which must NOT appear in the new versions.

You cannot open network sockets in this sandbox, so write the generator and the prompts; the owner's side runs it.
1. Look up Meta's image generation model ("Muse Image") in the Meta Model API docs and write `scripts/make_visuals.py`
   that reads the key the same way `upstream.py` does (never print it), sends each prompt from
   `docs/assets/visual_prompts.yaml`, saves PNGs to `docs/assets/generated/`, and records model, prompt and date in
   `docs/assets/generated/MANIFEST.md`. `--dry-run` prints the requests without the key. `--only NAME` runs one.
2. `visual_prompts.yaml`: the 8 storyboard panels without narration (1 typing a message with an email and a codename,
   2 live underlines, 3 risk card, 4 placeholders leave the PC, 5 answer restored locally, 6 contract clause becomes
   [CONTRACT_CLAUSE_1], 7 a coding agent tries to read .env and is stopped, 8 the decision log), a README banner
   (wide), a "Where Muse works" diagram background, and a social preview image. On-image text must be short and spelled
   out exactly in the prompt.
3. Code-drawn SVG fallbacks for the banner and the "Where Muse works" diagram (`docs/assets/banner.svg`,
   `docs/assets/where_muse_works.svg`; Glimmer = local judge, Spark = upstream AI and hosted judge, Voice = dictation,
   SAM 3.1 = image masks, Code = built it) so the README never depends on generation succeeding.
4. Tests: prompts file parses, every entry has a size and output name, dry-run output never contains the key, SVGs
   are valid XML. Run `python -m pytest -q`. Do not commit.
