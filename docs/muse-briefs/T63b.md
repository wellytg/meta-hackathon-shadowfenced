# T63b — Block card missing when the message has personal details AND a key (T63 changes are uncommitted here; keep them)

Live check of the T63 dev build (Playwright Chromium with `--load-extension=extension/dist/chrome-dev`, paired, local
app on 127.0.0.1:8765, test page on 127.0.0.1:8000). (probe script kept outside the repo)

- Message "Deploy with <AWS docs example key>" → click Send → card "Blocked — not sent / An AWS API key — not sent"
  appears within 0.7 s and stays. Correct.
- Message "Draft a reply to Ada Byron, ada.byron@northwind-mail.co, phone +44 20 7946 0958. Also deploy with
  <AWS docs example key>" → click Send → nothing is sent (good) but NO card appears at 0.2 s, 0.7 s or 2 s. The same
  silent stop happens on chatgpt.com (signed out, textarea composer) and gemini.google.com after Enter.
- The server answers both identically: `POST /api/ext/redact` → `{"decision":"BLOCK","safe_text":"","notes":"An AWS
  API key — not sent"}`. So the bug is in the extension (`extension/src/content.js`): likely the underline/hover-card
  state for the email/phone spans (a hover card open or pending, `hideCard` on overlay re-render, or the new T63
  capture-phase guard and the adapter path both handling the same send so one hides the other's card).

Fix so the send-time card always shows for BLOCK/HOLD/REDACT regardless of other spans or an open hover card (the
send card replaces any hover card and is not closed by overlay re-renders or a second handler; one send = one check =
one card). Add a regression test reproducing "PII spans present + key → BLOCK card visible", and one for the guard and
adapter not double-handling. Rebuild `python extension/build.py` and `--dev`. Run the extension tests,
`python -m pytest -q -p no:cacheprovider` and `python scripts/ci.py`. Do not commit.
