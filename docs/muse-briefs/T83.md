# T83 — First-visit intro, "Play the demo", tips, and disclaimer (UI only)

Audience: a hackathon judge opening the hosted demo for the first time, who may not want to type anything.
Change only files under `src/shadowfenced/static/` plus new tests. Do NOT edit README.md, `app.py`, or other
Python (another branch is editing them). Keep every existing element id in `index.html` (tests and recordings
use them). Do not commit; leave changes in the working tree and print a summary. Fictional data only. Plain
English, short sentences. Match the existing look (`style.css`, `welcome/welcome.css`); no new libraries, no
external requests, no inline event-handler attributes. Must work at phone width and with keyboard only.

## Build
1. **First-visit intro overlay** in the app (`index.html` + `app.js`): on first load (localStorage flag in
   try/catch; works without storage) show a dismissible card over the app: one line on what Shadowfenced is,
   three bullets (stops keys, swaps personal data for placeholders and restores them, works in chats, files and
   coding agents), and three buttons: **Play the demo** (see 2), **Try it yourself** (closes the card), **How it
   works** (opens `/welcome/`). Small print: "Public demo — use made-up data only." Esc and a close button
   dismiss it. A "?" button in the header reopens it.
2. **Play the demo:** runs the six cases one after another through the real `/api/send` endpoint, showing each
   in the chat as if typed (type-on effect, can be skipped), with a caption above each: 1 personal data →
   placeholders (fictional email), 2 a key in base64 (fake key built at runtime in JS from pieces, never a
   literal key-shaped string in the file — `tests/test_repo_guard.py` scans tracked files), 3 identity bundle
   (fictional name, birthday, address, phone, email) → blocked, 4 a pointer to where a key lives → held, then
   reviewed, 5 a harmless question → allowed and answered, 6 a coding-agent line explaining the `/v1` proxy with
   a copy button for the curl from README. Stop button at any time. Reuse the app's own send/render code so the
   real decision cards appear. Wait for each answer or hold result before the next case.
3. **Tips panel:** a small "What counts as sensitive?" button that opens a side panel: keys and tokens (and
   where they live), personal data, identity combinations, client and contract text, bank details, files —
   each with one fictional example and what Shadowfenced does with it.
4. **Footer line on the app and on `/welcome/`:** "Hackathon build. Use at your own risk — see SECURITY.md.
   Built from scratch for the Meta Global AI Developer Hackathon, Oct 26 – Nov 4, 2026." with links to the GitHub
   repo, `SECURITY.md`, and `docs/JUDGES.md` on GitHub
   (`https://github.com/wellytg/meta-hackathon-shadowfenced/blob/main/...`).
5. **`/welcome/` refresh:** add near the top a "See it in 2 minutes" row: links to the demo video
   `https://youtu.be/A5oB9gPYrfg`, **Play the demo** (`/?play=1`, which starts the player), the guide for
   judges, and the repo. Add a simplified "How a message is decided" diagram as inline SVG with 4 boxes
   (1 Code rules · 2 Muse Glimmer on your GPU (Muse Spark in this hosted demo) · 3 Code checks the model ·
   4 You decide) and an arrow to "Only placeholders reach the cloud AI". Keep the existing sections; fix any
   claim that does not match README.md.

## Tests
Add tests (pytest with FastAPI TestClient, like the existing static/UI tests) that: the intro markup and the
play/tips buttons exist; `/?play=1` serves the app; the footer text and links are on both pages; no key-shaped
strings in static files (the repo guard covers it). Run the full suite (deselect the two timing tests from
`setup/AGENT_SETUP.md`); all must pass. Also `node -e` a syntax check of every changed .js file.
