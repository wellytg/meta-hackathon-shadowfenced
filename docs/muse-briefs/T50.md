# T50 — Chat UI fixes found in the browser test of the risk card build

Found by driving the real page (`/api/send` responses from the live app). Keep the square Classic style and every id
and `data-testid`. Read `static/app.js`, `docs/UI_STATES.md` (§17 risk card) first.

1. **WARN gets the wrong receipt.** For a `decision: "WARN"` response the message shows the receipt
   "? Not sent — couldn't check" above the risk card, and the details drawer shows `DECISION UNKNOWN`. WARN must be a
   known decision everywhere: receipt label "Waiting for you — review" (amber), drawer shows `WARN`. Check every
   decision value the server can return (`ALLOW, REDACT, WARN, HOLD, BLOCK`) maps to a receipt label and a drawer
   value; "couldn't check" is only for real transport/parse failures.
2. **After "Send anyway" or "Generalise" succeeds** the card must change to its final state ("Sent anyway — you chose to
   send" / "Sent generalised"), the receipt updates, and the choice buttons disappear. Today the old receipt and the
   buttons stay.
3. **Duplicate banner.** The old re-identification banner under the composer ("Together, your name, date of birth and
   street address can identify and locate you." + Generalise) still appears next to the new risk card. Remove it from
   the send flow; the risk card is the one place for this. (Live typing underlines stay.)
4. **Drafts are wiped when a reply arrives.** Repro: type a message, press Enter, then type "draft" while the reply is
   loading; when the reply lands the composer is emptied and "draft" is lost. Also the sent text stays in the composer
   during the request. Correct behaviour (ChatGPT/Claude): on send, move the text into the user bubble and clear the
   composer immediately; keep anything typed afterwards; on failure put the sent text back only if the composer is empty,
   otherwise show it in the error line with a "Restore" control.
5. **Plain wording in "Why it's risky".** It currently says "A pii address and an address…". Use human labels per
   class ("a street address", "an email address", "a phone number", "a date of birth", "a project codename", "a contract
   clause", "an API key"), no internal class names, no duplicates.
6. Tests: extend the existing state-model tests for 1, 2, 4, 5 (pure functions or the existing harness). Run
   `python -m pytest -q -p no:cacheprovider`. Do not commit.
