# T31b — Second design round for the chat shell and themes

Look at the screenshots of your first round in `design-ref/review/` (console and welcome page, Classic and Fluid)
and compare them with `design-ref/` (DESIGN_SYSTEM.md, INTERACTION_SPEC.md, PAGE_BLUEPRINTS.md, ACCEPTANCE.md,
contact_sheet.jpg). The structure works; the presentation does not yet meet the spec. Fix these, then take your own
screenshots at 1440, 768 and 390 px in both themes with headless Chromium if your sandbox allows it, and compare
again before you finish.

1. **Header**: one slim bar (about 56–64px): wordmark left; model picker as a compact pill control in the centre
   ("Model: Muse Spark · cloud"); right side has a details-drawer toggle and a settings menu that contains Theme,
   Descriptive mode and Rules. No full-width select boxes, no stacked labels.
2. **Receipts instead of banners**: replace the full-width coloured banners under each turn with one compact
   receipt line in the message footer: an icon, a short label ("Sent", "2 details protected", "Review required —
   nothing sent", "Blocked — not sent", "Couldn't check — not sent") and a "Why" disclosure. Colour only on the
   icon and a thin left rule. Keep the existing `banner` test id on the receipt element so recorders still work.
3. **Details drawer**: make it real. It opens from the header toggle and shows, for the selected turn: decision,
   reasons, redaction summary with placeholder labels, the descriptive trace, model and timing; plus session counts
   and the log-chain status. Empty state text when nothing is selected.
4. **Fluid theme must look clearly different from Classic**: Chalk canvas, Paper surfaces, soft 1px Hairline
   borders instead of 2px ink outlines, 14px radii, 22px composer radius with a soft shadow, Manrope-like system
   grotesk stack, Flow/Amber/Coral states. Draw the **membrane**: a thin vertical line along the composer's send edge
   and between the conversation and the drawer, labelled PRIVATE / EXTERNAL in small caps on wide screens; it eases
   on release, firms (amber, still) on review, recoils once (≤240ms) on block; reduced motion turns these into
   instant colour/text changes. Classic keeps its hard outlines and safety orange.
5. **Landing page per theme**: in Fluid, the hero is an asymmetric layout with "Your words. Your boundary." and the
   membrane illustration; directly below the fold, the three-step story ("How most AI tools work" → "Where it goes
   wrong" → "With Shadowfenced") must be visible as three side-by-side panels on desktop and stacked on mobile, each
   with its inline SVG (a person and an agent sending a request that visibly contains an email, a contract clause
   and an API key from a .env file; the values highlighted leaving; then the membrane on the user's machine with
   placeholders crossing). Classic keeps its current look but gains the same three panels.
6. Keep every id and `data-testid`, all tests passing, no Python changes, no network, system fonts only.
   Run `python -m pytest -q`. Do not commit.
