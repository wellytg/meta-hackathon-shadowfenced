# T21 — Custom rules and descriptive mode

Files you own: new `src/shadowfenced/rules.py` (an APIRouter), new `src/shadowfenced/static/rules.js` and
`rules.css`, `src/shadowfenced/policy.py` (to merge local rules), new tests, and one line in `.gitignore`. In
`app.py` add only what is needed to include the router (before the static mount) and to add a `trace` field to the
JSON returned by `/api/scan` and `/api/send`. In `index.html` add only one `<link>` and one `<script>` tag. Do not
change existing behaviour or break existing tests.

1. Custom rules. `GET /api/rules` lists base rules from policy.yaml (read-only) plus custom rules. `POST /api/rules`
   adds one: `{kind: codename|client|pattern, value, action: block|redact|review, note?}`. `DELETE /api/rules/{id}`
   removes a custom rule. Custom rules are saved to `policy.local.yaml` at the repo root (path overridable with
   `SF_LOCAL_POLICY`), and that filename is added to `.gitignore`, because an organisation's codename list is itself
   sensitive. Validation: codename or client 2 to 64 characters; a pattern must compile, be at most 200 characters,
   and nested quantifiers such as `(a+)+` are rejected to avoid catastrophic backtracking. The engine applies custom
   rules as Tier 1 proven spans with the chosen action, immediately (no restart).
2. Descriptive mode. Build a step-by-step trace of how a decision was made, shown like a tool-call log: each step is
   `{step, tool, detail, result, ms}`, for example "tier1.canary_scan: 0 hits", "tier1.pii_scan: 1 email",
   "glimmer.judge: class=personal conf=0.7", "verifier: confirmed", "decision: REDACT". The trace must never contain
   raw sensitive values: use labels such as [PII_EMAIL_1] or short fingerprints. Do not write the trace into the
   decision log.
3. UI (rules.js and rules.css): a "Rules" drawer to view, add and remove custom rules, and a "Descriptive mode"
   toggle that renders the trace under each message as a compact step timeline. Plain, crisp styling; do not restyle
   existing elements.
4. Tests for the API, validation, the engine effect of a custom rule, and that traces contain no raw values.
   Run `python -m pytest -q` and report. Do not commit.
