# T59 — The Docker/Modal image cannot find policy.yaml or the web UI

The hosted Modal deploy (built from `Dockerfile`) answers `GET /api/health` with 200, but `GET /` is 404 and every
`POST /api/send` is 500 with:
`FileNotFoundError: /usr/local/lib/python3.12/policy.yaml` (from `policy.py` `_DEFAULT_PATH = Path(__file__).resolve().parents[2] / "policy.yaml"`).
Cause: the Dockerfile runs `pip install .` (a normal wheel install into site-packages), so `parents[2]` is
`/usr/local/lib/python3.12`, and `src/shadowfenced/static/` is not shipped in the wheel (no package-data in
`pyproject.toml`), so the static mount in `app.py` (~line 2447) finds nothing and `/` is 404. The same happens with
`docker compose up`. Other modules use the same `parents[2]` pattern (`config.py`, `corpus.py`, `judge.py`).

Fix:
1. In the `Dockerfile`, install so the source tree stays the import location: `pip install --no-cache-dir -e .`
   (keep `WORKDIR /app`, the COPY of `policy.yaml` and `src`, the non-root user, and `/app/runs` writable).
2. Also make the package robust: include `static/**` as package data in `pyproject.toml`, and let `policy.py` honour an
   env var `SF_POLICY_PATH` (falls back to the current default) — read at call time, not import time.
3. Tests: one test that `static/index.html` is declared as package data (parse pyproject), one that `SF_POLICY_PATH`
   is honoured (tmp_path policy), and one that reads the Dockerfile and asserts the editable install line.
4. Update `deploy/README.md` if it mentions the install step.
Run `python -m pytest -q -p no:cacheprovider` and `python scripts/ci.py`. Do not commit.
