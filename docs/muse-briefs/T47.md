# T47 — Provider key shapes: current formats and keys inside encodings must BLOCK

A browser test on the combined build found these gaps in `src/shadowfenced/tier1.py` (read it and its tests first):
- OpenAI project keys (`sk-proj-` followed by about 150 URL-safe characters, may contain `-` and `_`), OpenAI service
  account keys (`sk-svcacct-…`, `sk-admin-…`) and Anthropic keys (`sk-ant-api03-…`, `sk-ant-admin01-…`) are not
  matched as `provider_key`; they only reach the generic entropy check and get HOLD instead of BLOCK.
- A provider key wrapped in base64 (`KEY=AKIA…` base64-encoded) is not found at all for AWS, and only as entropy for
  others. The decode-and-rescan path must run the provider-key patterns on decoded text (base64, base64url, hex, URL
  encoding, and one level of nesting), the same way canaries and protected-key fingerprints are already handled.
