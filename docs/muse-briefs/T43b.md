# T43b — Real-run fixes for screenshot redaction

Measured outside the sandbox with `scripts/try_image_redact.py` on a synthetic 900x300 screenshot (email + phone):
- The run failed with `glimmer returned non-JSON content`. Calling Ollama directly with the same body showed Glimmer's
  answer was correct JSON followed by a stray special token:
  `{ "regions": [{"prompt": "email address", "box": [150, 25, 670, 65], "text": "marta.quill@…"}, {"prompt": "phone
  number", "box": [150, 135, 380, 175], "text": "+1 415 555 0134"}] }<|eot|>`
- The vision call took about 37 s on this PC (12 GB GPU). Without `"format": "json"` it ran to the length limit with
  empty content, so keep `format`.
- `meta-sam-parser` is not installed on the owner's PC yet.

Fix:
1. Parse tolerantly: strip `<|…|>` special tokens, then `json.loads`; if that fails, take the outermost `{…}` and try
   again; only then raise. Share this helper with the other Glimmer callers if one already exists (look in `judge.py`,
   `person_search.py`), otherwise put it in a small function in `image_redact.py`.
2. Vision timeout: a separate setting (default 120 s) for image calls; the UI shows "Checking image locally…" while it
   runs. Use `num_ctx` 2048 and a long `keep_alive` like the other Glimmer calls so the model does not reload.
3. If `meta-sam-parser` is missing, the app must not crash: log once, fall back to box fill, and the chip says
   "Box fill (SAM parser not installed)". `scripts/try_image_redact.py` prints which path was used.
4. Tests: the exact reply above (with `<|eot|>`) parses to two regions; a reply with prose around the JSON parses; parser
   missing → box fill with the right label. Run `python -m pytest -q -p no:cacheprovider`. Do not commit.
