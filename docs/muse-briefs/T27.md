# T27 — Audio uploads with Muse Voice Transcribe

Goal: a recorded meeting or voice note is transcribed by Meta's Muse Voice Transcribe model and then checked
exactly like any uploaded document, so spoken secrets are caught before the text reaches an AI.

1. Look up Muse Voice Transcribe in Meta's public developer documentation (dev.meta.ai / the Meta Model API docs and
   the meta-models cookbook on GitHub): the endpoint, request format, model id (expected `muse-voice-transcribe-1.0`)
   and response shape. Note the URLs you used in the module docstring. If the docs cannot be reached, implement
   against an OpenAI-compatible `/audio/transcriptions` endpoint at the configured Meta base URL and say so.
2. `src/shadowfenced/transcribe.py`: send an audio file (wav, mp3, m4a, ogg, webm; max 10 MB) using the existing Meta
   settings and TLS handling (truststore), return the transcript text. Errors and timeouts make the upload HOLD
   (fail closed), never pass.
3. Wire it into the existing upload path in `src/shadowfenced/uploads.py` / `extract.py`: audio files are transcribed
   and then go through the same scan; the file chip says "Transcribed by Muse Voice". Allow audio types in the file
   input in `index.html` (accept attribute only).
4. Tests with an injected fake transport (no network): transcript is scanned, a canary spoken in audio is blocked,
   errors hold. Run `python -m pytest -q`. Do not commit. Do not send real audio anywhere.
