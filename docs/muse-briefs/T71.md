# T71 — Setup kit: anyone (human or agent) can check their machine, start the app and try it in minutes

Judges and judge agents will try to run Shadowfenced. Make that fast and honest. Add a `setup/` folder. Do not change
detection behaviour. Never print, log or copy any key value (a key's presence may be reported as yes/no only). No
real-format provider keys in any file (the repo guard test fails on key shapes; build test keys at runtime or use
`SF_CANARY_` canaries). Synthetic data only.

## Facts to rely on (verify in code)
- Judge model is set by `SF_JUDGE_MODEL` (default `muse-glimmer:30b`); Ollama URL by `OLLAMA_URL`; the local upstream
  model by `SF_LOCAL_UPSTREAM_MODEL` (`llama3.2:3b`). See `src/shadowfenced/config.py`.
- With Ollama unreachable or the judge model missing, code tiers still run and hard cases fail closed (HOLD). Find the
  exact status text the app shows (`/api/status` or the System status panel: e.g. the `ollama` row) and quote it.
- Hosted mode `SF_HOSTED=1` uses Muse Spark as the judge. Live hosted demo:
  `https://wellytg--shadowfenced-asgi.us-east.modal.run` (fictional data only).
- Providers registry: `src/shadowfenced/providers.py` (Meta, OpenAI, Gemini, Anthropic, OpenRouter, Ollama local).
  Only Meta and Ollama were tested live — say so.
- API: `POST /api/send` with `{"messages":[{"role":"user","content":"..."}]}` returns `decision`, `user_message`,
  `evidence.reasons`, `trace`, `sent_text`. Proxy: `POST /v1/chat/completions` (403 block / 409 hold, header
  `X-Shadowfenced-Decision`).

## Build
1. `setup/README.md` (humans): three machine profiles in a table —
   **Full** (NVIDIA GPU ≥ 12 GB VRAM, Ollama, `muse-glimmer:30b`), **Light** (any machine with Ollama and ~4 GB free
   RAM/VRAM: Meta's `llama3.2:3b` as the judge via `SF_JUDGE_MODEL=llama3.2:3b`; also mention `llama3.2:1b`), **Code
   only** (no Ollama: code tiers only; more messages are held for you), and **No install** (the hosted demo). For each:
   what runs, what you lose, the exact commands (PowerShell and bash), and what the app shows. Leave a placeholder
   table "Measured on the final test set" with rows per profile (filled by T72).
2. `setup/AGENT_SETUP.md`: a prompt any coding agent can follow from a fresh clone: numbered steps, the exact command,
   the expected output for each step, how to verify (`setup/try_cases.py --local`), what to do on each known failure,
   and when to stop and report. Plain imperative sentences.
3. `setup/check.py` ("doctor", stdlib only, Windows/macOS/Linux): Python version (≥ 3.11), free RAM, GPU + VRAM via
   `nvidia-smi` if present (else "no NVIDIA GPU found"), Ollama reachable at `OLLAMA_URL`, which of
   `muse-glimmer:30b`, `llama3.2:3b`, `llama3.2:1b` are pulled, whether `META_API_KEY` is set or stored (yes/no only),
   whether the package is installed. Print a clear verdict: recommended profile + the exact start command + what will
   be degraded. `--json` for agents. Exit 0 always unless Python is too old.
4. `setup/start.ps1` and `setup/start.sh`: run the doctor, set `SF_JUDGE_MODEL` for the recommended profile (unless the
   user passes `-Profile full|light|code`), start uvicorn on 127.0.0.1:8765 and print the URL.
5. `setup/quick_cases.md` + `setup/try_cases.py`: 10 synthetic cases, each with the expected decision and why: a cloud
   key shape built at runtime (BLOCK), the same key base64-encoded (BLOCK), an email (REDACT, placeholder), a full
   identity bundle (BLOCK), a pointer "the prod key is in ~/.aws/credentials" (HOLD/flag), a name + employer welcome
   note (WARN), a bank row with sort code and account (REDACT or BLOCK — check), a contract clause, a harmless
   question (ALLOW), a person search (WARN/HOLD). `try_cases.py` runs them against the hosted demo by default,
   `--local` for 127.0.0.1:8765, `--url` for any; prints a table: case, expected, got, match, what was sent (the
   placeholder text, never values beyond the synthetic ones), latency. Options `--provider <id>` (destination model if
   connected) and `--json`. Handle a slow hosted cold start (retry once, 90 s timeout). Run it now against the hosted
   demo and against a local app if one is listening on 8765; if an expectation is wrong, fix the expectation only after
   checking the app's real behaviour is the intended one, and note it.
6. `setup/RESULTS.md`: every number the README claims → the file in `docs/results/` and the command that reproduces it
   (70 % settled by code, 27.5 % to a person, 26/26, 3/26, 7/14 from `eval_final_run3.json`; Tier 1 p50 0.45 / p95
   0.94 ms over 107 corpus messages — add `scripts/bench_tier1.py` that reproduces it). Copy
   `C:\meta-hackathon\work7\eval_final_run3_2026-11-03.json` to `docs/results/eval_final_run3.json` if not present.
7. Tests: unit tests for the doctor's profile choice (mock probes), for `try_cases.py` table/expectation logic (mock
   HTTP), and a guard that no file under `setup/` contains a key shape. Run `python -m pytest -q -p no:cacheprovider`
   and `python scripts/ci.py`. Do not commit.
