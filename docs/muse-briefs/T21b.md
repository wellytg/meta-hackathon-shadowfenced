# T21b — Make the rules route check work on current FastAPI

CI installs the latest FastAPI (0.162, Starlette 1.10) and `tests/test_t21_rules.py::
test_rules_routes_registered_before_static_mount` fails there: iterating `app.routes` no longer lists the routes
added with `app.include_router(...)` as flat `APIRoute` objects. Locally FastAPI 0.115 passes.

1. Rewrite that test so it does not depend on how FastAPI stores included routes: check the generated OpenAPI
   schema (`app.openapi()["paths"]`) for `GET`/`POST` on `/api/rules` and `DELETE` on `/api/rules/{rule_id}`, and
   check that these paths are matched before the static mount (for example by confirming the static mount is the
   last route and the rules paths resolve through `app.url_path_for` or the OpenAPI schema).
2. Review `src/shadowfenced/app.py` around `app.include_router(rules_router)` and the line that restores
   `app.router.lifespan_context`: keep startup behaviour identical on both old and new FastAPI. If restoring the
   lifespan is not needed or not safe on new versions, guard it so it only applies when the attribute changed.
3. Run `python -m pytest -q`. Do not commit.
