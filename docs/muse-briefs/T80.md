# T80 — "Prove all six" guide for judges

Goal: anyone can check each of the six things Shadowfenced catches in a few minutes, with no install where
possible. Branch `docs/judges-guide` (checked out). Do not touch README.md. Do not commit; leave changes in the
working tree and print a summary. Synthetic data only; never write a real-format provider key into a tracked
file (`tests/test_repo_guard.py`) — use the AWS docs example key only when built at runtime in code, and in docs
use key *pointers* or the base64 form already used by `setup/try_cases.py` if it passes the guard.

The six (from the video): 1 personal data → placeholders and restored answers; 2 works in ChatGPT and Gemini
(browser extension); 3 identity-theft bundle blocked in code; 4 files checked before upload with a one-click
redacted copy; 5 keys in any disguise (base64) and sentences that point to where a key lives; 6 coding agents
through the OpenAI-compatible proxy.

## Write
1. `docs/JUDGES.md`: one section per case: what it shows, exact text to paste (or file to upload), where to
   run it — **hosted demo** `https://wellytg--shadowfenced-asgi.us-east.modal.run` (fictional data only),
   **agent proxy** `<demo>/v1/chat/completions` with a copy-paste `curl` and an OpenAI SDK `base_url` snippet,
   **extension** (load unpacked from the v1.0-hackathon release zip, needs the local app; see
   `extension/README.md`), or **local** — and the expected decision and what you should see on screen. Add a
   short "Held messages" note: in the hosted demo Muse Spark reviews held messages (a few seconds), locally
   Muse Glimmer does. End with "Run all of them in one command": `python setup/try_cases.py`.
2. `docs/samples/`: small synthetic files for case 4: a fictional bank statement (CSV), a contact list (CSV),
   and a `.env`-style file whose values are pointers or clearly fake non-key-shaped strings. Check what the
   hosted demo's file upload accepts (read `src/shadowfenced/uploads.py` / `fileguard.py`) and say in the guide
   what decision each file gets.
3. Extend `setup/try_cases.py` only if a case from the six is missing from its 10 (keep it at ≤ 12 cases), and
   update `setup/quick_cases.md` to match.
4. With web tools, verify every hosted/proxy instruction in the guide against the live demo (max 1 request
   every 3 s) and write what you observed in `docs/JUDGES_verified.md` (timestamp, request, decision, status).
   If an instruction does not behave as written, change the instruction, not the product.

Run the test suite command from `setup/AGENT_SETUP.md` at the end (deselect the two timing tests); all must pass.
