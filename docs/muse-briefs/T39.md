# T39 — Fix Muse Voice: use Meta's real transcription API

Dictation and audio uploads fail with HTTP 404 because `src/shadowfenced/transcribe.py` calls
`{META_BASE_URL}/audio/transcriptions`, which does not exist. Meta's documented API (dev.meta.ai/docs/speech-to-text,
dev.meta.ai/docs/api-reference/voice/transcribe, and the cookbook folder `06_muse_voice/01_voice_api_fundamentals`):

- `POST https://api.meta.ai/v1/asr/transcribe` (base URL is the existing Meta base URL), header
  `Authorization: Bearer <Meta key>`, `Accept: application/json`.
- `multipart/form-data` with exactly two parts: `request` = JSON
  `{"model":"muse-voice-transcribe-1.0","audioEncoding":"WAV","mode":"PUSH_TO_TALK"}` sent with type
  `application/json`, and `audio` = the WAV file (`audio/wav`).
- Audio must be a RIFF/WAVE file, mono, 16-bit PCM, 16 kHz or 24 kHz. Max 32 MB (413), max 10 minutes (400);
  429 = rate limited; 500 = processing failure.
- Response JSON: top-level `transcript` holds the text (`turns` is empty in PUSH_TO_TALK).

1. Rewrite `transcribe.py` to this exact contract, keeping the existing TLS handling (truststore), timeouts and
   fail-closed behaviour. Map 400/413/429/500 to clear messages ("Recording too long", "Audio too large", "Muse Voice
   is busy, try again", "Muse Voice could not process this audio").
2. **Browser dictation**: in `dictation.js`, record with the Web Audio API (or MediaRecorder then decode with
   `AudioContext.decodeAudioData`), downmix to mono, resample to 16 kHz, encode 16-bit PCM WAV in the browser, and
   upload that to `/api/transcribe`. Keep the opt-in notice, the 60-second cap and the consent-only storage.
3. **Uploaded audio files** (wav, mp3, m4a, ogg, webm): convert to mono 16-bit 16 kHz WAV on the server before
   sending. Use Python's standard `wave` module when the input is already PCM WAV; for other formats use `ffmpeg` if
   it is on PATH, otherwise return a clear "Install ffmpeg to transcribe this format, or upload a WAV file" message
   (the upload then holds, never passes unchecked).
4. Tests with an injected fake transport: the request goes to `/v1/asr/transcribe` with the two multipart parts and
   the exact request JSON; the transcript is read from `transcript`; each error code maps to its message; a WAV
   produced by a small pure-Python encoder test helper matches mono/16-bit/16 kHz. A static test checks dictation.js
   builds a WAV header (RIFF/WAVE, 16000 Hz, 1 channel). Run `python -m pytest -q`. Do not commit. No network.
