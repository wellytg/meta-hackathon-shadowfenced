# T66b — Code detectors miss UK and international phone numbers

Keep the uncommitted T66 diff in this clone. Live test on the local app: "Draft a reply to Mara Voss, her number is
0161 496 0732 and email mara.voss@brightpost.net, saying the meeting moved." sends
"...her number is 0161 496 0732 and email [PII_EMAIL_1]..." — the phone goes to the AI. US formats (415-555-0132) are
caught. The Tier 1 phone detector (`src/shadowfenced/tier1.py`, the PII phone pattern) misses common non-US formats.

1. Detect as `PII_PHONE` (same redaction and placeholder flow as US phones): UK landlines and mobiles with spaces or
   none (`0161 496 0732`, `020 7946 0958`, `01632 960961`, `07700 900461`, `07700900461`), `+44 161 496 0732`,
   `+44 (0)20 7946 0958`, and general E.164 with spaces/dashes (`+1 415 555 0132`, `+49 30 901820`, `+61 2 9374 4000`).
2. Avoid false positives — these must NOT be phones: years and dates (`1815`, `03/05/1991`, `2026-11-02`), UK sort codes
   (`20-00-00`), card-like numbers (handled by the card detector), git SHAs, UUIDs, version strings (`1.4.14`),
   prices (`£1,250.00`), postcodes, order numbers explicitly labelled (`Order 1234567`), and 4-digit PINs. Use the
   existing context helpers (e.g. a nearby word like phone/tel/call/mobile/number raises confidence) where the
   pattern alone is ambiguous; keep Tier 1 fast (it must stay well under 20 ms on 4 KB).
3. Check the eval corpora still behave (`python scripts/eval.py --judge none` on cases/final/holdout, before and after;
   report numbers) and that no benign case flips to a false alarm because of this.
4. Tests for every format above (detected) and every false-positive class (not detected). Run
   `python -m pytest -q -p no:cacheprovider` and the extension tests. Do not commit.
