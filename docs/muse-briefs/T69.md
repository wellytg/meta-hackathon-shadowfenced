# T69 — Learns your habits, never your data: "What it caught" + rule suggestions

Owner's direction: never store what was blocked (that would itself be a leak), but let the person see what was caught
and let Shadowfenced propose rule edits from their patterns, so it gets out of their way over time. No model training.

## 1. Fix value fingerprints in the decision log (`ecs_log.py`)
Today `fingerprints` are unsalted `sha256(value)[:12]`. For low-entropy values (phone numbers, dates of birth, short
names) these can be brute-forced back to the value. Replace with HMAC-SHA256 under a per-install secret (32 random
bytes created on first use, stored via the existing keystore if available, else a local file outside the repo with
user-only permissions, path in settings; never logged, never sent). Keep the hash chain verifiable; old events keep
their old fingerprints and `verify` still passes. Test: same value → same fingerprint within an install; different
secret → different fingerprint; no raw value or unsalted hash in the file.

## 2. Record the person's choices (fields only)
When the person acts on a card (Send anyway, Generalise, Cancel, Make a redacted copy, Upload anyway, Apply/Dismiss a
suggestion), append a `choice` event to the same chained log: `{decision_id, choice, kinds, rule_ids, site (host only,
e.g. chatgpt.com / gemini.google.com / app), source (text|file), ts}`. Never values, never message text, never file
names. Wire it from the web app and the extension (send the choice to a token-guarded `POST /api/ext/choice`).

## 3. "What it caught" panel (web app, Classic style)
A Details/Settings tab listing recent detections and choices from the log: time, site, decision, kinds as chips, rule,
what the person chose. Filters by site and kind; counts per kind for the last 7 / 30 days. Clear text at the top:
"Only the type of item is recorded — never what you typed." A "Delete history" button that truncates the log after
writing a chained "history cleared" event.

## 4. Rule suggestions (`src/shadowfenced/suggest.py`, `GET /api/suggestions`, `POST /api/suggestions/<id>/apply|dismiss`)
Derive suggestions only from log patterns (kinds, rules, decisions, choices, sites, cue words), never from values:
- Same kind sent anyway ≥ 8 of the last 10 times (only PII kinds) → propose "hide it automatically and send" (REDACT
  instead of asking) for that kind, optionally per site.
- A cue word (e.g. 'born') held and released by Glimmer ≥ 10 times with no real finding → propose letting that cue pass
  without the model check when no Tier 1 finding is present.
- A kind redacted many times where the person always cancels → propose blocking it outright.
- A frequently hidden email domain → propose "Is <domain> yours? Add it as your organisation's domain" — the domain text
  is entered by the person in the card, never stored by the suggester (the suggester only knows "email from one
  repeated domain fingerprint").
Hard limits: suggestions can never relax secrets, canaries, keys, the full identity bundle, or person-search rules;
each suggestion shows the exact YAML change as a before/after diff against `policy.local.yaml`, plus the evidence
("you chose Send anyway 9 of 10 times in 7 days"). Apply writes `policy.local.yaml` (validated by the existing policy
loader), logs a chained `rule_change` event, and is undoable (keep the previous file as
`policy.local.yaml.bak-<ts>`). Also write the open suggestions to `runs/rule_suggestions.yaml` so a developer can
review them as a file.

## 5. Tests
HMAC fingerprints; choice events contain no values (fuzz with values in the message, assert absent from the log);
each suggestion rule triggers at its threshold and not below; hard limits hold (no suggestion ever relaxes a secret or
bundle rule even with 100 send-anyway choices — note those can't be sent anyway anyway); apply/undo round-trip;
hosted mode (`SF_HOSTED=1`) disables suggestions and the panel shows the public-demo notice. Run
`python -m pytest -q -p no:cacheprovider`, `python scripts/ci.py`, extension tests. Do not edit README.md. Do not
commit.
