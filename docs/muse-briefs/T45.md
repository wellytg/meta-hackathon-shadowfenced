# T45 — The risk card appears only on risky messages; clean messages get a quiet receipt

The core UX is the risk card: **what you are sending, why it is risky, what was done**. Read `static/app.js`,
`static/index.html`, `static/style.css`, `docs/UI_STATES.md` and the receipt code first. Keep the square Windows 3.11
Classic style (hard 2px outlines, radius 0, paper/ink, safety orange blocked, amber review, steel blue allowed) and
every existing id and `data-testid`.

1. Decision ALLOW with nothing found: no card. Show a one-line quiet receipt under the user's message:
   "✓ Checked · nothing sensitive" (text label, small, steel blue), with "Why" still available on click.
2. Any other decision (REDACT, WARN, HOLD, BLOCK): show the risk card attached to that message with three labelled rows:
   **Sending** (the message as it will leave, with placeholders highlighted, e.g. [PII_EMAIL_1]),
   **Why it's risky** (one plain sentence per finding, grouped, e.g. "An email address and a project codename",
   "Together these identify you: name + date of birth + street"), **What was done** (Replaced with placeholders /
   Blocked — not sent / Waiting for you: Generalise · Send anyway · Cancel). The title bar shows the decision word.
3. The card is compact by default (one line per row; "Show details" expands the full trace) so a long chat stays
   readable. It must work at 390px width.
4. The hold/review flow uses the same card model, so there is one component, not two.
5. Tests: a pure function `riskCardModel(decisionResponse)` exported via the existing test harness returns null for a
   clean ALLOW and the three rows otherwise; static checks that the quiet receipt text exists and the card has no
   border-radius. Run `python -m pytest -q`. Do not commit.
