# T28 — Agent demo using the Meta cookbook tool-calling pattern

Goal: show the agent gate catching a coding agent that reads a secret file, using Muse Spark tool calling as Meta's
cookbook teaches it.

1. Read the tool-calling / function-calling recipe(s) in the public `meta-models/meta-model-cookbook` repository on
   GitHub (Chat Completions with `tools`, `tool_choice: "auto"`). Note the recipe paths you followed in the docstring.
2. `examples/agent_demo.py`: a minimal agent loop in that pattern, pointed at Shadowfenced's OpenAI-compatible
   proxy (`http://127.0.0.1:8765/v1`), with two tools: `read_file(path)` restricted to `examples/sandbox/` and
   `list_files()`. `examples/sandbox/` contains a harmless `notes.md` and a `.env.demo` holding only a FAKE value
   for a protected variable (built at runtime from `SF_CANARY_` or a fake value configured through
   `SF_PROTECT_KEYS` in the demo, never a real-format provider key committed to the repo). The task given to the
   agent: "Summarise the files in the sandbox." Print each step: model tool call, tool result size, and the
   Shadowfenced decision for the next request (403 block / 409 hold / allowed), so the run reads like a log.
3. `examples/README.md`: what the demo shows and how to run it (app running locally, `--dry-run` mode that uses a
   scripted fake model so it runs without any API key).
4. Tests using the `--dry-run` fake model and the app test client: the request carrying the fake secret in a tool
   message is blocked and the fake value never appears in the forwarded request. Run `python -m pytest -q`.
   Do not commit. Do not call the real Meta API.
