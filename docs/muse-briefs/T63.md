# T63 — Browser extension: first live test found it does not guard ChatGPT, meta.ai, or show its status

First live run of the dev build (`python extension/build.py --dev`, loaded with Playwright Chromium
`--load-extension`, paired with the token from `GET /api/ext/pairing`, local app on 127.0.0.1:8765), on the test page
and on chatgpt.com, gemini.google.com and www.meta.ai while signed out. Message typed:
"Draft a reply to Ada Byron, ada.byron@northwind-mail.co, phone +44 20 7946 0958. Also deploy with <AWS docs example key>".
Real DOM captured from each site after focusing the composer is in `docs/muse-briefs/T63_domdump.json`.

Findings (fix all; read `extension/src/*.js`, `extension/README.md`, `src/shadowfenced/ext_api.py`):

1. **Popup always says "Not running — start Shadowfenced".** The background calls `GET /api/ext/health`, which the
   app does not have (app log: 404), while `/api/ext/scan` and `/api/ext/redact` work (200). Add a small
   `GET /api/ext/health` to `ext_api.py` (same origin + token guard as the other ext routes; returns
   `{"ok": true, "paired": <token valid>}`), and make the popup show "Connected" / "Not paired" / "Not running"
   correctly (network error = not running; 401/403 = not paired).
2. **ChatGPT is not guarded at all — the message, key included, was sent.** Signed-out chatgpt.com now serves
   `<textarea id="mobile-composer-prompt" aria-label="Chat with ChatGPT" placeholder="Ask ChatGPT">` and a send button
   `button[type=submit][aria-label="Send message"]`; none of the adapter's editor selectors (`#prompt-textarea`,
   `form div[contenteditable]`, ...) match. Add the textarea and `aria-label` based selectors (keep the old ones for
   signed-in ChatGPT, which uses `div#prompt-textarea[contenteditable]`), and `button[aria-label="Send message"]`.
3. **meta.ai composer is an `<input placeholder="Ask Meta AI anything...">`** (no textarea/contenteditable); send is
   `button[aria-label="Send"]`. Support `input` editors in the adapter, the underline overlay and the send interception.
4. **Fail visibly, never silently.** On a supported site where no composer is found (or the adapter breaks after a site
   update), show a small fixed badge "Shadowfenced: not protecting this page" and set the popup site row to amber.
   Also add a document-level capture-phase guard: on Enter (without Shift) or a click on any `button[type=submit]` /
   `[aria-label*="Send" i]` while focus is in any editable element on a supported host, run the same scan and block a
   BLOCK-level send even if the adapter did not attach. Fail closed if the app is unreachable: hold the send with the
   card "Shadowfenced is not running — message not sent" and a "Send anyway" choice (except secrets: never).
5. **Test page: clicking Send with the key showed no card** (nothing was sent, but no explanation appeared, "Nothing
   sent yet." unchanged). The send-time card ("Blocked — not sent") must appear for BLOCK, also when the popup thinks
   the app is down.
6. **Gemini shows "Attachment present — files are not..." with no file attached.** The attachment selector
   `[aria-label*="Upload" i]` matches the "Upload & tools" button. Count an attachment only from real attachment chips /
   a file input that actually has files, not from buttons.
7. **Gemini: the second half of the typed text was lost** after the hover card opened over the composer (typing after
   the card appeared did not reach the editor). The hover card must never take focus from the composer or swallow keys;
   it opens on hover/click of an underline only.

Tests (Node/logic tests like the existing ones under `extension/tests`, plus Python tests for the new route):
selector matching against the captured DOM snippets for all three sites; input-element support; fail-visible badge
when no editor; capture-phase guard blocks a key send with no adapter; app-down → held card; attachment detection
ignores buttons; hover card does not steal focus; `/api/ext/health` route with/without token. Rebuild with
`python extension/build.py` and `--dev`. Run `python -m pytest -q -p no:cacheprovider`, the extension tests, and
`python scripts/ci.py`. Do not commit.
