# T67 — Extension file guard: no file reaches an AI site unchecked

Today the extension only shows a badge "Attachment present — files are not scanned" (`extension/src/content.js`,
`updateAttachBadge`). The local app already extracts and scans uploads (`/api/upload`, `uploads.py`, `extract.py`,
`image_redact.py`, Tier 1, reid incl. the T66 full-identity-bundle rule). Build a real file guard. Principle from the
owner: better slow than leaked — a file the guard has not cleared must never reach the site.

## 1. Intercept (extension, all supported sites + `extension/testpage`)
- Catch files before the site sees them, in the capture phase at `window`: `change` on `input[type=file]`, `drop` (and
  `dragover` to allow it) anywhere on the page, and `paste` events carrying files. Stop the event
  (`preventDefault`, `stopImmediatePropagation`) and clear the input (`value = ''`) so the site never gets the file.
- Show a "Checking file…" card (same shadow-root card style as the text cards) with the file name and size.
- Send the file to the local app (see 2). App not running / not paired → card "Not checked — Shadowfenced app isn't
  running" and the file stays blocked (fail closed).
- Clean → card "✓ Checked · nothing sensitive in <name>" and an "Attach it now" button. Because re-injecting a file into
  each site's widget is fragile, use allow-once: the extension remembers the SHA-256 of the cleared file for 2 minutes
  and lets the next attach/drop/paste of that exact file pass untouched (one use). If re-dispatch via `DataTransfer` on
  the original `input[type=file]` works (testpage), do that automatically and keep allow-once as fallback.
- Risky → card "Blocked — not uploaded": file name, plain-words why (from the server; never values), chips of what was
  found with counts (e.g. "email address ×12", "AWS access key ×1"), and buttons "Make a redacted copy" and "Cancel".
  Secrets (keys, tokens, canaries) can never be overridden. Personal data only (no secrets, no identity bundle) may also
  offer "Upload anyway" behind a second confirm, consistent with today's text WARN/REDACT rules.
- Unscannable (unsupported type, encrypted PDF, extraction failed, too big) → "Blocked — couldn't check this file",
  with the reason; "Upload anyway (not checked)" only behind a second confirm.

## 2. Server (`ext_api.py`, token guard like the other ext routes, reuse existing extract/scan code)
- `POST /api/ext/scan-file` (multipart): limit 25 MB; returns `{decision: CLEAN|BLOCK|UNSCANNABLE, file_sha256, kinds:
  [{label, count}], why, has_secret, pages, chars, code_ms, deep_check: {available, estimate_seconds}, scan_id}`.
  Code detectors run on the full extracted text and decide immediately (must be about a second for a 40-page PDF).
- `POST /api/ext/redact-file` (`scan_id`): returns a redacted copy. Text-like files (txt, md, csv, json, code, env, log)
  keep their format with placeholders/`[… removed]`; DOCX and PDF become a redacted `.txt` named
  `<name>.redacted.txt` (say so on the card: "Saved as text — the layout isn't kept"); images use the existing local
  box-fill when available, else UNSCANNABLE. The extension saves the copy with a download (anchor + blob, or the
  `downloads` permission if needed — update `manifest.json` minimally) and tells the user to attach it. The redacted
  copy must scan CLEAN.
- Optional deep check: `POST /api/ext/deep-check` (`scan_id`) runs Muse Glimmer over the text in chunks, streams or
  polls progress (`GET .../deep-check/<id>`), and returns extra findings; estimate_seconds comes from chars and the
  measured Glimmer throughput (state the formula in code). The card shows "Deep check with Muse Glimmer — about N min"
  as an optional button with a progress bar; while it runs the file stays blocked. Deep check only adds findings, it
  can never clear a code finding.
- Hosted mode (`SF_HOSTED=1`): ext routes stay off as today.

## 3. Web app
Same outcomes in the app's own upload flow (`static/app.js`): "Blocked — not uploaded" card with chips, "Make a redacted
copy", deep-check option. Reuse the server functions.

## 4. Test page and samples
Add a file input and a drop zone to `extension/testpage/index.html`. Add synthetic samples under
`extension/testpage/samples/`: `bank_statement_synthetic.csv` (fictional bank "Corvane Credit Union", names, emails,
UK phones, sort codes, account numbers — all fictional), `team_contacts.txt`, `deploy_notes.env.txt` (contains a
SF_CANARY_ canary minted like `corpus.py` does, NOT any real-format provider key — `tests/test_repo_guard.py` fails on
key shapes in tracked files), `clean_meeting_notes.txt`. A small script `extension/testpage/samples/make_pdf.py` may
build a PDF version at test time; do not commit binaries larger than 200 KB.

## 5. Tests
Server: scan-file CLEAN/BLOCK/UNSCANNABLE, kinds and counts, never values in the response, 25 MB limit, token guard,
redacted copy scans CLEAN, deep-check can't clear a code finding, estimate is positive and scales with size, 40-page
synthetic text scans in < 2 s. Extension (node tests on logic.js): interception decision table, allow-once by hash
(one use, 2-minute expiry), fail closed when app is down, secrets never overridable. Run
`python -m pytest -q -p no:cacheprovider`, `python scripts/ci.py`, and
`for f in extension/tests/*.test.js; do node --test "$f"; done`. Update `docs/ARCHITECTURE.md` briefly. Do not commit.
