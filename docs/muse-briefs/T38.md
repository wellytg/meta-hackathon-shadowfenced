# T38 — Standard chat look and feel, top status indicator, phone layout, log viewer

Use a subagent with web access to look at how widely used AI chat apps lay out their chat screen (ChatGPT, Claude,
Gemini, Meta AI; their public pages, help-centre screenshots and design write-ups). Write `docs/CHAT_UI_PATTERNS.md`
with the common pattern you find. Do not copy any logo, icon artwork or brand name; follow the common layout only,
in our Classic style (paper background, ink text, hard outlines, safety orange, steel blue, amber).

1. **Composer like a normal chat app**: one rounded box pinned to the bottom of the conversation column, centred
   with a max width (about 760px); the text area grows upward to about 8 lines then scrolls; **Attach (+) in the
   bottom-left corner inside the box; microphone and Send in the bottom-right corner inside the box**; Enter sends,
   Shift+Enter makes a new line; Send is disabled when empty. Dictation status ("Listening…", errors) appears as a
   small line inside the box, not as a separate block. Do not change dictation.js logic beyond moving its button into
   the right-hand corner slot (`#composer-tools`).
2. **Top status indicator** in the header: "Model: Muse Spark · cloud" (from the model picker) and "Guard: on ·
   checking locally (code + Muse Glimmer)" with a state dot; if the local Glimmer is unreachable, say "Guard: on ·
   code checks only". Descriptive mode stays the "show more detail" switch in Settings; add a disabled "Developer mode
   (coming soon)" item.
3. **Phone layout (≤ 640px)**: the conversation and composer fill the screen; the chat list and the details drawer
   become slide-out panels opened from header buttons; nothing stacks under the composer. Remove all leftover Fluid
   "PRIVATE / EXTERNAL" membrane labels and related CSS.
4. **Decision log viewer** in the details drawer: a "View log" button opens a list of recent decisions (time,
   outcome, tier, reasons, fingerprints only, never raw values) with the chain-verified status. Add a read-only
   endpoint `GET /api/log/events?limit=50` returning those fields from the existing hash-chained log.
5. **Pairing token** in the drawer: hidden by default with "Show" and "Copy", plus "Regenerate" (new endpoint `POST
   /api/ext/pairing/regenerate`, local-only, invalidates the old token). Explain in one line: "Paste this into the
   Shadowfenced browser extension. It lets only your extension use this app."
6. Keep every id and `data-testid`. Tests for the new endpoints (log events contain no raw values; regenerate
   invalidates the old token), composer structure (attach left, mic/send right slots), and the phone-layout structure.
   Run `python -m pytest -q`. Do not commit.
