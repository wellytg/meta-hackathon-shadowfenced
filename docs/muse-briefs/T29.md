# T29 — Financial account details and document-type warnings

Today a pasted or uploaded bank statement has its card number, address and phone numbers caught, but the account
number, routing number and account holder name are not recognised, and nothing tells the user what kind of document
they are about to share.

1. **New Tier 1 detectors** (code, proven spans, class `pii`, new subclasses), each with tests:
   - bank account numbers: 6–17 digits next to a label ("account number", "acct", "a/c", "checking", "savings",
     "account no."), including masked forms like ****8841 (masked forms are low sensitivity, never block);
   - US ABA routing numbers: 9 digits next to "routing", "ABA" or "RTN", accepted only if the ABA checksum is valid;
   - IBAN: country code + check digits + BBAN, accepted only if the ISO 13616 mod-97 check passes; UK sort code +
     account number pairs ("sort code 20-00-00, account 12345678");
   - SWIFT/BIC next to "SWIFT" or "BIC";
   - account holder / patient / employee names after labels such as "Account holder:", "Name:", "Patient:",
     "Employee:", "Cardholder:".
   Redaction placeholders follow the existing style, e.g. [PII_ACCOUNT_1], [PII_ROUTING_1], [PII_IBAN_1].
2. **Document-type warning**: classify a message or uploaded file as `bank_statement`, `medical_record`,
   `payslip`, `contract` or none, from documented weighted signals (for example statement period, opening/closing
   balance, transactions table, routing/account numbers for bank statements; MRN, diagnosis, medication, insurance
   member ID for medical records; gross/net pay, tax code, employer, pay period for payslips; "this agreement",
   "party", "governing law", "indemnif", "confidential" for contracts). When detected, show one plain warning above
   the decision, for example "This looks like a bank statement. It usually contains account numbers, balances and
   your address." A contract warning says it may contain confidential terms and party names. The warning is shown
   in the UI receipt, included in the decision evidence and the descriptive trace (`doc.classify`), and does not by
   itself block; the existing decisions still apply.
3. Tests with fictional examples only (use valid-checksum test numbers you compute yourself, e.g. routing 021000021,
   IBAN GB82WEST12345698765432, 555 phones, invented names). Add 6 fictional documents to `corpus/documents/` (two
   bank statements, two medical records, one payslip, one contract) and a test that each is classified correctly and
   its account/routing/IBAN/holder details are caught.
4. Do not change existing behaviour beyond adding these. Run `python -m pytest -q`. Do not commit. No network.
