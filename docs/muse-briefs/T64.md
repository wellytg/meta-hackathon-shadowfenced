# T64 — "Person search" label fires on ordinary messages that just mention a contact

Live check (local app, Muse Glimmer 30B loaded; browser extension and `/api/ext/redact`):
"Draft a reply to Mara Voss, her number is 415-555-0132 and her email is mara.voss@brightpost.net" returns
`decision: HOLD` with the person-search banner "This message names a person and gives details that identify them (their
full name). If this is you ... If it's someone else: ... looking up a private person can expose them to harm. Rule:
Person search." Drafting a reply to a contact is not a search for a person. A warning is fine (name + phone + email is a
real re-identification combination → the "Combined identifying details" rule), but the person-search rule, title and
"looking up a private person" text are wrong here. The T62b code fallback already requires search wording
(`person_search.has_search_wording`); the Glimmer path (`local_glimmer_person_search`, and the hosted Spark judge) does
not.

Fix (read `person_search.py`, `engine.py` `_apply_person_search`, `reid.py`, tests for person search and T62/T62b/T62c):
1. Treat a message as a person search only when the request is to FIND / LOOK UP / IDENTIFY / LOCATE information about
   the person (search wording via `has_search_wording`, or the model judgement says intent is lookup AND the message has
   search/lookup intent words). Messages that ask to write to, reply to, summarise for, schedule with, or describe a
   contact are not person searches; they fall back to the existing re-id outcome ("Combined identifying details", or
   REDACT with placeholders) — unchanged behaviour otherwise.
2. Make the model prompt ask explicitly for intent (lookup vs other) and require lookup for the person-search verdict.
3. Keep the T48 public-figure behaviour and the T62c card text for real searches ("Find everything about Daniel Whitmore,
   born 14 March 1987, lives in Leeds" must still give the person-search card).
4. Tests: the Mara Voss reply message → no person-search rule (re-id rule / REDACT instead); "Find everything about
   Daniel Whitmore, born 14 March 1987, lives in Leeds" → person search; "Look up Theo Lindqvist at 8 Harbor Lane" →
   person search; "Is Theo Lindqvist a good hire? He lives at 8 Harbor Lane." → not person search (re-id/REDACT);
   with mocked judges for local Glimmer and hosted Spark. No values in reasons.
Run `python -m pytest -q -p no:cacheprovider` and `python scripts/ci.py`. Do not commit. Never write key-shaped strings
in any file.
