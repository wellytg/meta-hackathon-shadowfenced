# T65 — Remove the example.com / example.org / example.net email allowlist

Decision by the owner: emails at example.com, example.org and example.net must be treated like any other email
address (flagged as personal data), so a demo or a judge typing `name@example.com` sees the same card as any real
domain. Today `policy.yaml` `allowlist.email_domains` lists those three domains, and `policy.email_allowlisted`
(`src/shadowfenced/policy.py`) plus `tier1.py` skip them.

1. Make `allowlist.email_domains` an empty list in `policy.yaml` (keep the key and the `shapes` list). Keep the
   allowlist mechanism itself working: a user may still add their own domain.
2. Update tests that relied on the example domains being ignored (`tests/test_tier1.py` around line 203 and 337,
   `tests/test_t30c_reid.py` around lines 104-131, and any others you find): where the test was about the allowlist,
   test it with a domain set in a test-only policy; where the example email was only filler, assert it is now flagged
   or switch to text without an email, whichever keeps the test's intent. Check docs (README, docs/) for any sentence
   saying example.* addresses are ignored and update it.
3. Run `python -m pytest -q -p no:cacheprovider` and `python scripts/ci.py`. Do not commit.
