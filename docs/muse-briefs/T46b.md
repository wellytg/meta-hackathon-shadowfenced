# T46b — Fix make_visuals.py after a real run on the owner's PC

Measured results outside the sandbox (the owner's side ran the calls):
- `GET /v1/models` lists `muse-image-1.0` (not `muse-image-1`); `muse-image-1` returns 404 `model_not_found`.
- `POST https://api.meta.ai/v1/images/generations` with `{"model":"muse-image-1.0","prompt":…,"size":"1024x1024"}`
  returns 200 JSON `{"created":…,"data":[{"b64_json":"…"}]}` and the decoded bytes are **WebP** (RIFF/WEBP header),
  about 1600x1600 px, not PNG.
- The script failed with `RuntimeError` because TLS verification on this PC needs the OS trust store: reuse the exact
  verify logic from `upstream.py` (`truststore` SSLContext with fallback), do not write a new one.

Fix:
1. Default model `muse-image-1.0`.
2. Decode `b64_json`, detect the format by magic bytes, and save as PNG with Pillow (convert WebP → PNG). If a
   requested size is not square, request the nearest supported square size, then crop/resize locally with Pillow to the
   size in the YAML (centre crop), and note it in MANIFEST.md.
3. Print a short per-item line (`ok banner.png 1280x400` / `error banner: <status> <message>`), never the key, and keep
   going after one failure; exit non-zero if any failed.
4. Tests with an httpx MockTransport returning a tiny WebP made with Pillow in the test: PNG saved at the YAML size,
   manifest written, failure of one item does not stop the others. Run `python -m pytest -q -p no:cacheprovider`.
   Do not commit.
