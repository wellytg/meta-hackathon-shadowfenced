# T31 — Chat-app shell, two themes (Classic and Fluid), and a clearer landing story

Read the design spec in `design-ref/` first (AGENT_BRIEF.md, DESIGN_SYSTEM.md, INTERACTION_SPEC.md,
PAGE_BLUEPRINTS.md, ACCEPTANCE.md, tokens.css, contact_sheet.jpg). It is a reference, not code; do not copy it into
the repo. Then inspect the real code (`src/shadowfenced/static/`, `app.py`, `rules.js`, the tests) before changing it.

Use subagents: an **auditor** (map routes, UI states, API responses and every `data-testid`; write
`docs/UI_INVENTORY.md`), a **designer** (theme tokens and components), and a **builder** (the shell and pages).

## Goals
1. **It should feel like a normal AI chat app** (in the spirit of ChatGPT or Claude, but with its own identity, no
   copied logos or layouts): a left sidebar with "New chat" and the list of this session's chats, a model picker at
   the top fed by `/api/providers` (Meta Muse Spark in the cloud, Llama 3.2 local, and whatever the server lists),
   the conversation in a central column, the composer at the bottom with Attach and Send. Each assistant turn gets
   one compact decision receipt ("Sent", "2 sensitive details protected", "Review required — nothing sent",
   "Blocked — not sent") that expands to show why. The decision counts, trace, rules and log move into a collapsible
   right-hand details drawer instead of a permanent rail. Chats are kept in memory for the page session only (never
   written to localStorage or the server), because they may contain sensitive text.
2. **Two themes, switchable from settings and remembered with localStorage (theme name only):**
   - **Classic**: the current crisp paper-and-ink look (hard 2px outlines, safety orange, steel blue).
   - **Fluid**: the "Fluid Containment" system from `design-ref/` (Chalk/Paper/Ink palette, Flow/Amber/Coral
     states, the thin membrane line between PRIVATE and EXTERNAL that eases on release, firms on review and recoils
     once on block). Light first, with a dark variant.
   Both themes use the same markup; themes only change tokens and a few component styles.
3. **Landing page (`/welcome/`) tells the story in three steps**, using the active theme:
   (a) "How most AI tools work": a person or an AI agent sends prompts, files and tool output through an API
   straight to a cloud model; the request carries whatever was in it (an email, a contract clause, an API key from a
   .env file). (b) "Where it goes wrong": highlight those values travelling out. (c) "With Shadowfenced": the same
   flow with the membrane on the user's machine; secrets blocked, personal and company details swapped for
   placeholders, the real values restored locally in the answer. Use inline SVG and CSS animation, clearly labelled
   "Illustration". Then "How it works" (the four tiers as they really work), "What stays on your machine", and
   "Open the app". Hero line: "Your words. Your boundary." Only claim what the code does.
4. **Never fake a state**: every receipt and membrane state comes from the real server response; unknown states
   show as neutral and never as sent. No raw sensitive values in DOM attributes, URLs, logs or animation state.

  Keyboard reachable, visible focus, 44px touch targets.
