# T34 — Voice dictation with Muse Voice (opt-in)

1. Add `POST /api/transcribe`: accepts one short audio clip (webm/ogg/wav/m4a, max 60 seconds, max 5 MB), sends it
   to Muse Voice Transcribe using the existing `src/shadowfenced/transcribe.py`, and returns `{"text": "..."}`. It
   never forwards the text to any chat model; errors and timeouts return a clear error (no text). Disabled in hosted
   demo mode unless `SF_HOSTED_DICTATION=1`.
2. New `src/shadowfenced/static/dictation.js` and `dictation.css` (one tag each in `index.html`). The script adds a
   microphone button (`data-testid="mic-btn"`, aria-label "Dictate") into `#composer-tools` if that element exists,
   otherwise next to the Attach button. Clicking it the first time shows a one-time notice: "Dictation uses Meta Muse
   Voice in the cloud. Your voice is sent to Meta to be turned into text. The text is then checked here before it goes
   to any AI." with "Turn on dictation" and "Cancel". Only the consent flag is stored (localStorage key
   `sf-dictation-consent`), never audio or text.
3. Recording: MediaRecorder; button shows recording state and elapsed time; click again or 60 s stops. The
   transcript is inserted at the cursor in the composer (data-testid `composer`) and the normal live scan runs, so
   underlines appear before sending. Nothing is sent automatically.
4. Handle no-microphone and permission-denied cases with a plain message. Respect reduced motion. Keyboard
   accessible.
5. Tests: endpoint with an injected fake transport (text returned, size/duration caps, error path, hosted-mode
   default off); static checks that dictation.js targets `#composer-tools`, shows the notice before first use, and
   stores only the consent flag. Run `python -m pytest -q`. Do not commit. No network.
