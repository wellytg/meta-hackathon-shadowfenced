# T48 — Re-identification must not warn about historical or public figures

A browser test found: "Summarise the life of Ada Lovelace, born 10 December 1815 in London." gets WARN with "Together,
your name, date of birth and city can identify and locate you." That is wrong: the person is historical and the user
is asking about a public record, not sharing their own details. Read `src/shadowfenced/reid.py`,
`person_search.py`, the re-identification tests, and `docs/` notes on the sealed sets first (do not open or edit the
sealed set `final.yaml` if present anywhere; tune only on the holdout/tuning set and new tests).

Fix:
1. Date-of-birth evidence for a birth year more than 110 years before today does not count as a quasi-identifier for a
   living person (it cannot locate anyone alive). Same for a death date in the text ("died 1852").
2. Public-figure / encyclopedic framing ("summarise the life of", "biography of", "who was", "what did … invent")
   plus a name that Glimmer recognises as a well-known public figure lowers the score so the outcome is ALLOW, unless
   the message also includes a current street address, phone, email or ID number (then the usual rules apply).
   Glimmer's judgement must be a local call with a short timeout; if Glimmer is unavailable fall back to rule 1 only.
3. Never weaken: the Dana Whitlock examples (a private person, born 1991, street) must still WARN, the people-search
   example must still WARN, and "my name is …, born …, I live at …" must still WARN.
4. Tests: historical figures with old dates → ALLOW (Ada Lovelace 1815, Isaac Newton 1643, a made-up 1870 painter);
   living public figure question without private details → ALLOW with Glimmer mocked as "public figure"; Glimmer
   unavailable → old-date rule still works; existing re-identification tests unchanged and passing. Run
   `python -m pytest -q`. Do not commit.
