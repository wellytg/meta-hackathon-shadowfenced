# T61 — Hosted demo: the decision log is never written, so counters stay at 0

Live check of the hosted demo (Modal, `SF_HOSTED=1`, built from `Dockerfile`, app created in `deploy/modal_app.py`):
after a REDACT send, `GET /api/stats` returns `{"total":0,...}` and `GET /api/log/events` returns `[]`; the Decisions
card shows 0 for everything and System status says "log chain verified · 0 events". `_log_decision` in `app.py`
swallows every exception (`except Exception: pass`), so the failure is invisible. The default `log_path` is the
relative `runs/decisions.jsonl` (`config.py`), resolved against the process working directory, which on Modal is not
guaranteed to be `/app`; the image also switches to a non-root user, so the directory may not be writable.

Fix:
1. `ecs_log.resolve_path`: resolve a relative log path against the project root (the same root `policy.py` uses), not
   the CWD, unless `SF_LOG_PATH` is absolute.
2. `deploy/modal_app.py`: set `SF_LOG_PATH` to a writable absolute path (e.g. `/tmp/shadowfenced/decisions.jsonl`)
   before importing the app; note in `deploy/README.md` that the hosted log is per container and resets on restart.
3. `_log_decision` (and the WARN-confirmation log write near `app.py` line 1590): keep "never fail the gate", but
   log one warning with the exception type and path (never message text), and expose the last write error in the
   `log` health line (status `degraded`, "log not writable: <ExceptionType>") so it cannot hide again.
4. Tests: relative path resolves against the project root regardless of CWD (chdir to tmp_path); a write failure (e.g.
   path in a read-only/nonexistent location via monkeypatch) is reported in health as degraded and does not break
   `/api/send`; modal_app sets SF_LOG_PATH (static check of the file).
Run `python -m pytest -q -p no:cacheprovider` and `python scripts/ci.py`. Do not commit.
