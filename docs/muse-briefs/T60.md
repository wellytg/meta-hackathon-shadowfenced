# T60 — Hosted public demo: honest status, no local-only panels, nothing clipped

Live check of the hosted demo (`SF_HOSTED=1`, Modal) in Chrome at 1308x924 found:

1. **System status shows false alarms.** `ollama` is red "Down — Ollama unreachable: ConnectError" and `keystore` is
   yellow "Degraded — no OS credential backend; .env fallback in use". In hosted mode both are expected: Tier 2 uses the
   Muse Spark fallback (`hosted.judge_for_review`) and the Meta key comes from the host secret. In `health.py`, when
   hosted, report `ollama` as status `off` with detail "Not used in the public demo — Muse Spark does the Tier 2 check"
   and `keystore` as `off` with "Not used in the public demo — the key comes from the host's secret store". Make sure
   `off` renders as a neutral grey badge (not red/yellow) in `static/app.js`/CSS and does not make the overall health
   look failed. Local mode is unchanged.
2. **Pair browser extension panel must not appear on the public demo.** It shows a pairing token to every visitor and
   the extension only pairs with a local app. When hosted: hide the panel in the UI, have `GET /api/ext/pairing` return
   403 `{"code":"shadowfenced_hosted_pairing_disabled"}`, and report the `extension` health line as `off` "Not used in
   the public demo — the extension pairs with the app on your own PC".
3. **Provider key controls are shown but refused.** In hosted mode the header Providers panel still shows "Paste key",
   Save, Test connection and Disconnect, though key storage returns 403 (`_refuse_hosted_storage`). When hosted, hide
   those controls and show one line: "Public demo: uses the host's Muse Spark key. Run Shadowfenced on your PC to use
   your own keys." Provider switching that needs a stored key is hidden too.
4. **Header label.** Header says "Guard: on · code checks only" although the hosted demo also runs the Muse Spark
   check. When hosted say "Guard: on · code checks + Muse Spark review". Keep local wording as is.
5. **Public-demo banner covers the header.** The banner is `position: fixed` (about 31 px) and sits over the sticky
   header (the logo and controls are cut off at the top). Put the banner in normal flow above the header (or offset the
   header and layout by the banner height) so nothing is covered, at desktop and 390 px widths.
6. **Details drawer is clipped and cannot scroll.** `.side-col` has `overflow: hidden` and height 1118 px while
   `details.details-drawer` content is 1372 px; `.drawer-body` has `overflow-y: auto` but no bounded height, so the
   bottom (System status end, Pair panel) is cut off with no scrollbar. Fix the flex/grid sizing so the drawer body fills
   the column and scrolls (e.g. side-col `display:flex; flex-direction:column; min-height:0`, drawer `flex:1;
   min-height:0`, drawer-body `overflow-y:auto; min-height:0`). Check local mode too: all cards reachable by scrolling.
