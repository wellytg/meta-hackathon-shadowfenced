# T30 — Re-identification risk: catch details that identify a person only in combination

Problem: a single detail (a first name, a birth year, a town) is often harmless, but together they identify or
locate a person. Studies of US records found that date of birth + ZIP code + gender alone single out most people.
An attacker (or a curious AI) can also infer identity or location from what remains after redaction, for example
"[PII_NAME_1], the only paediatric surgeon at the Fairhaven clinic, born 1988". Shadowfenced should catch both.

Use subagents. Start three, each with a clear brief, and combine their work:
- **researcher**: write `docs/REID.md` — quasi-identifiers (name, date of birth or age, street address, postcode,
  city, employer, job title, school, gender, distinctive medical condition, vehicle plate, unique dated events),
  why combinations matter (k-anonymity, linkage attacks, OSINT), which combinations are high risk, and how to
  generalise values while keeping the message useful (date of birth → birth year, street address → city, full
  postcode → first 3 characters, exact job title → job family).
- **red team**: write `corpus/reid.yaml` — 40 fictional cases: 25 risky (combinations in one message; details
  spread across several messages of one conversation; residual clues left after obvious redaction; indirect
  descriptions like "the tallest guy in accounts who drives the yellow Mini") and 15 safe controls (one isolated
  detail, public figures in public roles, details about a fictional character in a story). Each case says the
  expected outcome and which details form the risky combination. Use only invented people and places, 555 phone
  numbers, and example.* or corvane.io emails.
- **builder**: implement and test the feature below.

Feature (files you own: new `src/shadowfenced/reid.py`, small hooks in `engine.py` and `tier1.py`, the trace
builder, new `src/shadowfenced/static/reid.js` and `reid.css` loaded with one tag each in `index.html`, new tests,
`scripts/eval.py` support for the new corpus). Existing behaviour and tests must not change.

1. **Quasi-identifier extraction** (code, Tier 1): find the quasi-identifiers listed above with spans and a kind.
2. **Combination risk** (code): score the set found in the message, and across the messages of one request or UI
   conversation. Use explicit, documented weights; high-risk pairs/triples (name + date of birth, name + street
   address, date of birth + postcode + gender, employer + job title + city) push the message to a new outcome
   `WARN` (shown to the user with the reason, user may send anyway) or `HOLD` above a higher threshold. The banner
   says in plain words which details combine, e.g. "Together, your name, date of birth and street address can
   identify and locate you."
3. **Generalise instead of delete**: offer a one-click "Generalise" choice that rewrites only the risky details to
   coarser values (as in REID.md) and shows the before/after; the real values stay local as today.
4. **Residual-context check (inference reversal)**: after redaction or generalisation, if the remaining text still
   has 2+ quasi-identifiers, ask local Muse Glimmer to act as an OSINT analyst on the redacted text only:
   `{"can_identify": bool, "can_locate": bool, "clues": ["<exact substring>", ...]}`. Code (Tier 3) keeps only clues
   that are exact substrings of the redacted text. Two or more verified clues with `can_identify` or `can_locate`
   → HOLD with those clues listed. Glimmer errors or timeouts → HOLD (fail closed). Never send this check to a cloud
   model.
5. **Trace**: add steps `reid.extract`, `reid.combine` (score and the combination), `reid.residual` (verified
   clues as labels or fingerprints, never raw values).
6. **Tests and eval**: unit tests for extraction, scoring, conversation-level accumulation, generalisation, the
   residual check with a fake judge, fail-closed behaviour, and that no raw values reach traces or logs. Extend
   `scripts/eval.py` with `--corpus reid` and report catch rate and false-warning rate.

Run `python -m pytest -q`. Do not commit. Do not use the network.
