# T49 — One shared Ollama context size for every Glimmer call (stops 18 s model reloads)

Measured on the owner's PC: `judge.py` and `person_search.py` call Ollama with `options.num_ctx = 2048`, but the
residual inference check in `reid.py` (around the `"think": False` call) sends no `num_ctx`, so Ollama uses the model
default (8192). Every switch between the two sizes makes Ollama reload the 17 GB model (about 18–19 s), so the
person-search intent check always hits its 10 s timeout ("Glimmer could not check intent") and the residual check is
slow too.

Fix:
1. Add one setting in `config.py`, e.g. `glimmer_num_ctx` (default 2048, env `SF_GLIMMER_NUM_CTX`) and a small helper
   (e.g. `glimmer_options(**extra)` in `judge.py` or a new tiny module) that every local Glimmer call uses for its
   `options`, including `keep_alive` set to a long value (e.g. "30m") so the model stays resident.
2. Use it in every place that calls Ollama: `judge.py` (both calls), `person_search.py`, `reid.py`, the startup warm-up
   in `app.py` lifespan, and `health.py` if it calls the model. The warm-up must use the same options so the first
   real check does not reload.
3. Test: a static test that greps `src/shadowfenced/` for Ollama request bodies (`/api/chat` or `/api/generate`) and
   asserts each one gets its options from the helper (no literal `num_ctx` anywhere else); a unit test with an httpx
   MockTransport that captures the request bodies of judge, person_search and reid and asserts identical `num_ctx`
   and `keep_alive`. Run `python -m pytest -q`. Do not commit.
