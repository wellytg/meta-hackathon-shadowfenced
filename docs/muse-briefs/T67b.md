# T67b — File guard does nothing in a real browser: the FileList is emptied before it is read

Keep the uncommitted T67 diff. Live test (Chromium + dev extension, paired, test page `#fileInput`, Playwright
`set_input_files` with `samples/bank_statement_synthetic.csv` and `samples/clean_meeting_notes.txt`): the site never
receives either file (good) but no card appears and `/api/ext/scan-file` is never called; the clean file is not passed
through either. Cause, in `extension/src/content.js` `bindFileGuard` change handler: `files = t.files` is the input's
live FileList; then `input.value = ''` empties that same FileList; then `fgCheckFiles(files, …)` copies zero files and
returns at `if (!list.length) return;`.

1. Copy the files into a plain array before clearing the input (`Array.prototype.slice.call(t.files)`), in the change,
   drop and paste paths (check drop/paste for the same live-list problem with `DataTransfer.files`/`items`).
2. Make `fgCheckFiles` fail visible: if called with no files after an interception, show the "Not checked" card instead
   of returning silently.
3. Add a node test that simulates a live FileList which empties when `value` is cleared and asserts the scan is still
   called with the file; and one for drop.
4. Run the extension tests and `python -m pytest -q -p no:cacheprovider`. Do not commit.
