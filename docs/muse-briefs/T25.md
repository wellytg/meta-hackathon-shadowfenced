# T25 — Container and hosted demo mode

Goal: anyone can run Shadowfenced with one command, and it can be hosted as a public demo without a GPU.
Hosting must not depend on any single provider.

1. `Dockerfile` (python:3.12-slim, non-root user, installs the package, runs uvicorn on port 8765 bound to 0.0.0.0
   inside the container) and `.dockerignore` (exclude `.env`, `runs/`, `.git`, caches, `policy.local.yaml`).
2. `compose.yaml`: service `shadowfenced` (build `.`, port 8765, `env_file: .env` marked optional) and an optional
   `ollama` service profile for local Glimmer, with the app pointed at it through the existing Ollama URL setting.
3. Hosted demo mode, turned on by `SF_HOSTED=1`:
   - a fixed banner on the console and splash page: "Public demo. Use made-up data only.";
   - custom rules are kept in memory only (never written to disk) and capped at 20;
   - uploads are capped at 1 MB; requests are rate-limited per client IP (simple in-memory token bucket);
   - when no local Ollama is reachable, Tier 2 uses Muse Spark through the existing Meta upstream client as the
     judge, with the same typed verdict schema and the same Tier 3 code verification; this is clearly labelled in the
     trace as "judge: Muse Spark (hosted demo)". Local mode behaviour is unchanged.
4. `deploy/modal_app.py`: a Modal app that serves the same ASGI app with `SF_HOSTED=1`, reading the Meta key from a
   Modal secret named `shadowfenced-meta`. `deploy/README.md`: how to deploy on Modal, and alternatively as a Hugging
   Face Docker Space using the same Dockerfile. Neither is required to run locally.
5. Tests for hosted mode (banner present, rules not persisted, caps enforced, judge fallback selected when Ollama is
   unreachable, using fakes, no network). Run `python -m pytest -q`. Do not commit. Do not run docker or network.
