# T63c — A key must block instantly; the extension must wait honestly (T63 + T63b changes are uncommitted here; keep them)

Measured on the local app (Glimmer loaded in Ollama), `POST /api/ext/redact`:
- "Deploy with AKIAIOSFODNN7EXAMPLE" → BLOCK in 0.014 s
- "Draft a reply to Ada Byron, ada.byron@northwind-mail.co, phone +44 20 7946 0958." → 7.5 s
- the same + " Also deploy with AKIAIOSFODNN7EXAMPLE" → BLOCK after 15.8 s

So a message that already holds a proven secret still waits for Muse Glimmer (and other model checks) before
returning a BLOCK that was certain from Tier 1. And the T63b extension now times out the send check after
`SEND_CHECK_TIMEOUT_MS = 1500` and shows "Shadowfenced isn't running — start it or turn the extension off" although the
app is running and answering (it is just slow) — the app log shows the extension did not even wait for `/api/ext/redact`.

Fix:
1. **Engine short-circuit (`engine.py` and the ext redact route):** when Tier 1 finds a proven span whose action is
   BLOCK and `user_can_keep` is false (secrets, canaries, protected keys), return BLOCK immediately and skip every model
   call (Glimmer Tier 2, person search, cue review, contract/model checks). Precedence BLOCK > everything makes this
   safe; the decision, reasons (add "proven secret -> BLOCK (model checks skipped)"), placeholders policy and log
   record must otherwise be unchanged. Apply on `/api/send`, `/api/scan`, the proxy and `/api/ext/*`. Test: with a
   transport that fails the test if called, a key + PII message returns BLOCK and makes no model call; a PII-only message
   still calls the model as before.
2. **Extension wait states (`extension/src/content.js`):** on send, show a "Checking…" card at once (Classic look,
   amber), update it with elapsed seconds, and replace it with the result card when the answer arrives. Allow up to
   45 s (the app's own Glimmer timeout is the real limit). Show "Shadowfenced isn't running" ONLY on a network error /
   refused connection; on 401/403 show "Not paired — open the Shadowfenced popup and paste the pairing token"; on a 45 s
   timeout show "Still no answer — nothing was sent" with Retry. Keep one send = one check = one card (T63b).
3. Tests: engine short-circuit (above); extension: slow answer (10 s) → checking card then the BLOCK card; network error
   → not running; 401 → not paired; timeout → retry card. Rebuild `python extension/build.py` and `--dev`. Run the
   extension tests, `python -m pytest -q -p no:cacheprovider` and `python scripts/ci.py`. Do not commit.
