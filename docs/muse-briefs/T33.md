# T33 — Person-search intent: Glimmer reads the whole statement

Code already finds identifying details and scores combinations (`src/shadowfenced/reid.py`). Code cannot tell
intent: "When was [a historical figure] born and where did he live?" is ordinary research; "Find everything you can
about Dana Whitlock, born 14 March 1991, Copperleaf Drive, Fairhaven" is a search for a private person.

1. **When to ask Glimmer**: if the message (or conversation) has a person's name plus at least one other
   quasi-identifier, or people-search wording ("find", "look up", "everything about", "where does … live", "who is",
   "dig up", "background on", "contact details for"), send the whole message to local Muse Glimmer with a typed
   schema: `{"person_search": bool, "subject_public": bool, "subject": "<exact name substring or empty>",
   "inferred": ["<short fact the message reveals or seeks, each tied to an exact substring>"], "confidence": 0-1}`.
2. **Code checks the claim** (Tier 3): keep only `subject` and `inferred` items whose referenced text appears exactly
   in the message. If `person_search` is true, `subject_public` is false and confidence ≥ 0.6 with a verified subject,
   the outcome is `WARN` (never block). Public figures in their public role and historical figures are not flagged.
3. **Warning content**: plain words plus what Glimmer could already infer from the message, for example "This looks
   like a search for a private person. From this message alone, an AI can tell: their full name, their date of birth,
   their street and town. Sending it shares those details with the AI provider, which may refuse or log the request."
   Offer the existing Generalise choice. The user can still send.
4. **Never cloud**: this check uses only local Glimmer. If Glimmer is unavailable or times out, fall back to the
   existing code-only re-identification result and say "Glimmer could not check intent" in the trace; do not block.
5. Add the trace step `intent.person_search` (labels/fingerprints only, never raw values) and include the warning in
   decision evidence as `person_search` so the UI can show it in the receipt notes area.
6. Tests with a fake judge: private-person search warns; historical/public figure does not; unverifiable claims are
   dropped; Glimmer failure falls back; no raw values in traces or logs. Add `corpus/person_search.yaml` with 20
   fictional cases (12 searches for private people, 8 public/historical or harmless) and `scripts/eval.py --corpus
   person_search`. Run `python -m pytest -q`. Do not commit. No network.
