# T36 — Browser extension: Grammarly-style checking inside ChatGPT, Claude, Gemini and Meta AI

Goal: a user keeps using the AI chat site they already use. As they type, the extension underlines sensitive text
(like a grammar checker does), explains it on hover, offers "Replace with placeholder", and checks the message again
when they press send. All checking is done by the user's own Shadowfenced running on 127.0.0.1; nothing goes to any
other server. Use subagents: one for the local API, one for the extension, one to test.

## Local API (small, new module `src/shadowfenced/ext_api.py`, mounted with one line)
- `POST /api/ext/scan` `{text}` → spans with class, label and placeholder suggestion (reuse Tier 1 and the existing
  live scan; no cloud calls). `POST /api/ext/redact` `{text}` → `{decision, safe_text, notes}` where safe_text has
  placeholders; the mapping stays in server memory keyed by a short-lived id (15 min). `POST /api/ext/rehydrate`
  `{id, text}` → text with real values restored, for display only on the user's screen.
- Pairing: the extension must send a pairing token in a header. The app generates it on first run, shows it in the
  console settings ("Pair browser extension"), and rejects requests without it. Only `chrome-extension://` and
  `moz-extension://` origins or no origin are accepted. Never log text or values.

## Extension (`extension/` folder, Manifest V3, one codebase)
- Works in Chrome and Edge (MV3) and Firefox (MV3 with `browser_specific_settings.gecko.id`); a small build script
  `extension/build.py` writes `dist/chrome/` and `dist/firefox/` and zips them. No third-party libraries, no remote
  code, no analytics.
- `host_permissions`: `http://127.0.0.1:8765/*` and only the four sites: chatgpt.com, claude.ai,
  gemini.google.com, meta.ai. Permissions limited to `storage` (pairing token and on/off switch only).
- Content script: finds the message box (textarea or contenteditable), debounces input (about 400 ms), asks the
  background service worker to call `/api/ext/scan`, and draws underlines in an overlay layer inside a closed shadow
  root positioned over the editor (never rewriting the site's DOM while typing). Hover card: what was found and two
  actions, "Replace with placeholder" and "Ignore".
- On send (Enter or the send button): run `/api/ext/redact` first. BLOCK → stop the send and show "Blocked — not
  sent" with the reason. REDACT → replace the editor text with safe_text, show "2 details protected", then let the
  user press send again. HOLD/WARN → show the reason with "Send anyway" / "Cancel". If the local app is not running or
  any call fails, stop the send and say "Shadowfenced isn't running — start it or turn the extension off" (fail safe).
- Answers: watch the AI's reply area and replace placeholders it echoes with the real values on screen only, using
  `/api/ext/rehydrate`; mark restored values with a subtle highlight.
- Popup: status (connected / not running), pairing token entry, per-site on/off.
- Site adapters in one file with selectors per site, easy to update; if no adapter matches, do nothing.

## Docs and tests
- `extension/README.md`: install for testing (Chrome/Edge: Load unpacked from `dist/chrome`; Firefox:
  about:debugging → Load Temporary Add-on from `dist/firefox`), pairing, what it does and does not cover (typed and
  pasted text; file attachments only get a warning), and the honest limit: it is a guard rail; the proxy and API path
  are the hard boundary.
- Python tests for the three endpoints (pairing required, origin check, mapping expiry, no values in logs). JS logic
  that can run in Node without a browser (span-to-range mapping, adapter selection, fail-safe decision table) gets
  tests runnable with `node --test` if Node is available; otherwise pure-function checks in Python via a tiny
  harness. Validate both manifests with a Python test (required keys, permissions limited as above).
Run `python -m pytest -q`. Do not commit. No network.
