# T55 — Screenshot redaction: an empty Glimmer answer must not mean "clean"

Live test on the combined build (`/api/upload`, image redaction mode "local", a synthetic 900x300 PNG with an email
address and a phone number in plain black text): the first upload right after choosing the mode returned
`status: clean, regions: 0` and the image came back unchanged; two retries a minute later each returned 2 regions
(email, phone) and box-filled them (about 18 s each). So one Glimmer answer of `{"regions": []}` let a sensitive image
through. Read `src/shadowfenced/image_redact.py` and the upload route in `app.py`.

Fix:
1. Two-pass check: pass A is today's region finder. Pass B asks Glimmer only to transcribe all visible text line by line
   with boxes (short JSON), and the code runs the Tier 1 detectors on that text; any Tier 1 hit whose line box is known
   is filled even if pass A missed it. Run pass B always when pass A returns zero regions; otherwise only when cheap
   (setting, default on).
2. If both passes return nothing but the image clearly contains text (pass B returned lines), the result is "clean —
   checked by Muse Glimmer on this PC" (honest wording). If pass B also fails to answer, status is "unscannable" and the
   image is held, never sent.
3. Tests with mocked transports: pass A empty + pass B finds an email line → the line is filled and status flagged; both
   fail → unscannable; pass A finds regions → pass B skipped when the setting is off. Keep using the shared Glimmer
   helpers in `glimmer.py`. Run `python -m pytest -q -p no:cacheprovider` and `python scripts/ci.py`. Do not commit.
