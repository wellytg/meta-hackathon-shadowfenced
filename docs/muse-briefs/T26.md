# T26 — Rules to dataset, local fine-tune, and evaluation

Goal: an organisation's rules become training data, Muse Glimmer labels it on the local machine, and a small Meta
open-weight model (Llama 3.2 3B) is fine-tuned with QLoRA on a 12 GB GPU to act as a fast, rule-aware judge.
Write the scripts and tests only. Do not run anything that uses the network or a GPU.

1. `scripts/ft_generate.py`: reads `policy.yaml` (and `policy.local.yaml` if present), and asks Muse Spark through
   the existing Meta upstream client to write short, realistic workplace messages for the fictional organisation:
   leaks per class (secret, personal, business, beacon) that use the rules, near-misses that look risky but are
   safe, and plainly safe messages. Output JSONL to `runs/ft/raw.jsonl` with `{id, text, intended_class, rule_ids}`.
   Deduplicate, cap length, and never include real-format provider keys (use `SF_CANARY_` canaries).
2. `scripts/ft_label.py`: runs the existing Tier 1 + Muse Glimmer judge (local Ollama) over the raw set and writes
   `runs/ft/labeled.jsonl` with the typed verdict `{cls, is_beacon, sensitivity, confidence, span}`; drops rows where
   Glimmer disagrees with `intended_class` into `runs/ft/disputed.jsonl` for review.
3. `scripts/ft_split.py`: deterministic train/val/test split (80/10/10, seeded), with the test split written
   separately and never used for training.
4. `scripts/ft_train.py`: QLoRA SFT of `meta-llama/Llama-3.2-3B-Instruct` (transformers + peft + bitsandbytes,
   4-bit, LoRA r=16) on the chat format "message → verdict JSON", sized for a 12 GB GPU (batch size, gradient
   accumulation and max length chosen to fit), saving the adapter to `runs/ft/adapter/`. Add an
   `[project.optional-dependencies] finetune` group in pyproject.toml; do not add these to the base dependencies.
5. `scripts/ft_eval.py`: on the test split, compare the base 3B, the tuned 3B and Glimmer: class accuracy, beacon
   F1, leak rate (sensitive rows judged safe), false-alarm rate, valid-JSON rate and p50/p95 latency. Write
   `runs/ft/eval.json` and a Markdown table.
6. `docs/FINETUNE.md`: the pipeline, why distillation (Glimmer is accurate but slow; the 3B is fast), data is fully
   synthetic, and exact commands. Tests for parsing, splitting determinism and dataset hygiene (no key-shaped
   strings), using fakes. Run `python -m pytest -q`. Do not commit.
