# T37 — Use the full check on every route

Bug: re-identification (`reid.py`) and the person-search intent check (`person_search.py`) only run inside
`engine.gate_reid()`, which only the browser-extension API calls. The chat send path (`/api/send`), the live scan
(`/api/scan`), file uploads, the held-message review, and the OpenAI-compatible proxy (`/v1/chat/completions`) call
`engine.gate()` and never reach them. Example that must change: sending "Find everything you can about Dana
Whitlock, born 14 March 1991, who lives on Copperleaf Drive in Fairhaven." through `/api/send` today returns the old
"possible pointer to sensitive data" hold with no re-identification or person-search evidence.

1. Make one authoritative gate function used by every route (merge `gate_reid` into `gate` or have `gate` call it),
   so Tier 1, documents, re-identification, person-search intent, Glimmer review and verification all run in one
   consistent order. Keep the existing precedence: BLOCK > HOLD > REDACT > WARN > ALLOW; a model can never unblock
   what code proved; errors fail closed except the person-search check, which falls back to the code-only result.
2. WARN behaviour in `/api/send`: nothing is sent upstream; the response carries the warning (banner, combination,
   what Glimmer could infer, Generalise option) and a way to confirm ("send anyway" or "send generalised") through a
   follow-up request that reuses the same decision id. In the proxy, WARN is reported in the response metadata and
   the request proceeds only if the client sets an explicit header `X-Shadowfenced-Accept-Warn: 1`; otherwise 409 with
   the warning, like a hold.
3. The live scan returns re-identification findings so the composer can underline combinations as you type.
4. Integration tests that go through the real HTTP routes (TestClient or the existing direct-call helpers used in
   this repo's tests): the Dana Whitlock example warns through `/api/send` with re-identification and person-search
   evidence; a historical/public figure question does not; "send anyway" and "send generalised" work; the proxy
   returns 409 without the accept header; uploads of a text file containing name + date of birth + address warn; no
   raw values appear in traces or logs. Run `python -m pytest -q`. Do not commit. No network.
